Claude Code 历史对话：从本地记录到可搜索的知识

处理过的 bug、架构讨论和命令排错，经常留在 Claude Code 的旧 Session 里。你可以先找到原始会话，再决定是否把它们纳入跨工具知识库。AIKS 的本地 Provider 只读取允许的来源，不会写回 Claude Code 原始文件。

如何找到 Claude Code 的本地历史？

Claude Code 的项目会话通常保存在用户目录下的 .claude/projects/ 中，常见格式为 JSONL。具体位置可能随系统、版本与用户自定义配置变化；请以实际目录和 AIKS 数据源检测结果为准。

~/.claude/projects/

用 AIKS 查找和复用记录

  1. 确认会话来源

    打开 AIKS「数据源」，找到 Claude Code。检查检测目录和健康状态；便携安装或非默认目录可手动指定绝对路径。

  2. 只读扫描历史 Session

    启用需要的来源后执行扫描与同步。在「工作记录」中按项目、来源或标题查找旧会话，核对时间和原文。

  3. 使用全文检索

    先用日志关键字、错误信息、框架名或命令检索历史内容。关键词检索不要求配置模型。

  4. 按需提炼知识

    需要把长对话沉淀为结论时，再在设置中配置并启用 AI 服务。语义检索需要额外配置 Embedding；两者默认不必开启。

哪些内容值得保留？

例如一次 .NET 编译故障：会话中的报错、尝试过的命令、最终修复和适用范围可以关联为知识，后续搜索时仍能回到原始 Session 核对。AI 总结不应取代原始证据。

支持范围与隐私边界

  • 不从 Claude 账号云端批量下载全部私有历史；只处理当前机器上允许读取的本地来源。
  • 若项目曾迁移、使用不同用户目录或会话格式发生变化，请重新检查来源路径和格式兼容性。
  • AIKS 对原始 Provider 文件只读；生成的知识、状态和可选 SiYuan 同步与原始会话分离。

实际格式以可复核的兼容矩阵为准，不应假定工具的每个版本都支持。 多数据源兼容矩阵.

常见问题

没有配置 AI 模型也能搜索 Claude Code 历史吗？

可以浏览已导入的会话并使用关键词检索；自动知识提炼和 AI 问答需要配置模型。

会修改 Claude Code 的 JSONL 文件吗？

不会。AIKS 的本地 Provider 按只读方式访问来源。

能直接看到所有云端 Claude 对话吗？

不能。本地 Claude Code 会话与 Claude 网页端账号中的私密聊天并不是同一种来源。
