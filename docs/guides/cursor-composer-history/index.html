CURSOR · COMPOSER 历史

Cursor Composer 历史记录：找回项目里的 AI 编程过程

Cursor 的聊天记录可能散落在不同工作区、Composer 会话或 Agent 文件中。AIKS 把 Cursor 与 Cursor Agent 作为不同的本地来源处理，避免将不兼容的文件格式误认为已支持。

Cursor 聊天历史保存在哪里？

在受支持的 Cursor Composer 布局中，AIKS 读取编辑器 User 目录下 globalStorage/state.vscdb 和 workspaceStorage/<workspace>/state.vscdb 的相关记录。Cursor Agent 是另一类来源，读取 ~/.cursor/projects/<project>/agent-transcripts/ 下的 JSONL。并非所有 Cursor 聊天和任意版本的格式都被支持。

globalStorage/state.vscdb
workspaceStorage/<workspace>/state.vscdb

用 AIKS 查找和复用记录

  1. 区分 Cursor 与 Cursor Agent

    打开「数据源」，分别查看 Cursor（Composer 数据库）和 Cursor Agent（本地 transcript）是否可用。它们的来源 ID、根目录与可读格式不同。

  2. 确认实际 User 数据目录

    Windows、macOS、Linux 的编辑器 User 路径不同。若使用便携配置、远程配置或不同用户目录，请在数据源设置里明确指定。

  3. 只读导入再搜索

    扫描后使用工作记录的来源筛选和关键词搜索查找项目对话。遇到损坏数据库或尚未完成的写入，查看来源诊断，不要直接修改源数据库。

  4. 核对再提炼结论

    对有价值的架构决定、调试步骤或配置经验，可选择启用 AI 提炼；保留原始 Session 以便回溯。

为什么不能承诺所有 Cursor 聊天都能导入？

Cursor 的存储布局和字段会变化。AIKS 对 Composer JSON、关联 bubble 与部分旧 workspace Composer 列表进行了有界格式支持，但对其他未验证的聊天 Schema 不做保证。实际导入是否完整应以当前安装版本与来源检查为准。

支持范围与隐私边界

  • Cursor Composer 的 SQLite 数据库与 Cursor Agent JSONL 属于不同 Provider，不能混为一种格式。
  • SQLite 来源只读；不写入编辑器设置，不读取无关账户凭据。
  • 已导入会话不会因为关闭某个来源就自动删除；遇到未知格式应记录可脱敏样例再完善适配。

实际格式以可复核的兼容矩阵为准，不应假定工具的每个版本都支持。 多数据源兼容矩阵.

常见问题

Cursor 和 Cursor Agent 是同一个数据源吗？

不是。一个读取受支持的 Composer 数据库布局，另一个读取 Agent transcript JSONL。

为什么某些 Cursor 对话没有出现？

可能属于未覆盖的格式、工作区路径或尚未支持的版本；先检查来源诊断和兼容矩阵。

会影响 Cursor 正在使用的数据库吗？

AIKS 按只读方式读取来源，包括受支持的 SQLite/WAL 状态，不主动修改原文件。

快速了解

只读采集 → 工作记录搜索 → 按需知识提炼。
