CODEX CLI · 历史会话

Codex CLI 历史会话：查找之前的命令与解决方案

Codex CLI 的一个 Session 可能包含文件修改思路、Shell 命令、工具输出与问题定位过程。与其逐个回忆会话名，不如把本地历史导入后统一检索，同时保留可追溯的原始来源。

Codex CLI 的历史记录在哪里？

典型的 Codex CLI 安装会将历史 Session 保存在用户数据目录（常见为 ~/.codex/sessions/）下。不同版本和自定义 CODEX_HOME 环境可能改变位置。AIKS 依据实际支持的本地格式读取，不会调用你的账号接口下载云端私密历史。

~/.codex/sessions/

用 AIKS 查找和复用记录

  1. 检查 Codex CLI 来源

    在「数据源」确认 Codex CLI 已被发现。对非默认目录使用明确的路径配置，避免误把安装目录作为会话目录。

  2. 导入工作记录

    执行只读扫描后，进入工作记录，选择 Codex CLI 来源。原始对话和任务状态分别查看，不把同步成功等同于知识已提炼完成。

  3. 从错误或项目找回会话

    优先搜索报错原文、函数名、Shell 命令、仓库关键字；再打开匹配的原始 Session 检查上下文。

  4. 把结论留在项目知识中

    根据需要启用 AI 提炼，保存具体修复原因、实施步骤与来源引用。语义搜索可选，不依赖它才能查看旧会话。

跨工具检索为什么有用？

同一个项目可能先在 Codex CLI 调试，又在 Claude Code 或 Cursor 中继续。统一项目和来源视图可以帮助定位讨论过的方案，但 AIKS 不会自动断言不同会话描述的是同一个事实。

支持范围与隐私边界

  • 本页介绍 Codex CLI 本地会话；不声称支持任何版本的全部事件格式或私有云端历史。
  • Provider 只读，导入异常或文件损坏不会因此改写来源。
  • 知识提炼需要明确配置 AI 服务；使用本地模型还是远程 API 由你选择。

实际格式以可复核的兼容矩阵为准，不应假定工具的每个版本都支持。 多数据源兼容矩阵.

常见问题

为什么我看不到旧的 Codex 会话？

先确认安装用户、CODEX_HOME 或其他自定义数据目录，再查看数据源健康状态和格式兼容性。

导入会重新执行历史 Shell 命令吗？

不会。采集历史是读取记录，不是重放命令或工具调用。

可以同时搜索 Claude Code 和 Codex 的记录吗？

可以在 AIKS 的统一会话/知识视图中按来源和项目查找已导入的记录。

快速了解

只读采集 → 工作记录搜索 → 按需知识提炼。
