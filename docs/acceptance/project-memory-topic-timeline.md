# S3.1 项目记忆主题与更新轨迹验收入口

项目记忆页面需展示按**既有知识 category** 确定性分类的主题计数和筛选按钮：架构与决策、环境与配置、实施记录、问题与解决、研究与探索、明确标记的约束和待办、其他。每条知识只能进入一个主题，未识别类别必须保留在“其他来源记录”，不得凭标题或正文猜测任务完成或事实正确。

组合验收：在同一个项目导入来自 Codex / Claude Code / OpenCode 的结构化知识，部分知识带 `incorrect`、`needs_detail`、`outdated` 用户反馈。切换类别并勾选“仅需人工复核”，列表只能包含两个条件同时匹配的当前已加载知识；切换项目应恢复全部主题和列表视图；所有可见条目仍可点击到知识详情和原始 Session。

点击“按知识更新时间线”后，按知识最后更新时间从近到远显示，不把更新时间叙述为事件发生或方案生效时间。相同日期的稳定排序以及损坏/缺失日期的“时间未记录”均必须经过回归；切回列表不改变原始数据。

**数据与隐私边界**：主题数和时间线仅覆盖工作台已有最多 200 条有界样本，截断时明确提示；与 S3.2 的按日期和来源、SQL 层先过滤的全项目报告机制不同。没有自动抓取新的 Provider 原始文件、没有写回 SiYuan 或 Agent 指令，不依赖新的远程服务。此验收入口需要用户在最后 Windows 真机集中验收阶段使用真实项目和内嵌 SiYuan 检查，固定单测与 CI 均不等同于这些结果。
