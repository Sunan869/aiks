# S3.3 人工精选 Agent 知识包：来源验证与离线安全验收

使用独立 Windows AIKS 数据目录采集 Codex、Claude Code、OpenCode 的多个项目会话，将同名但不同真实绝对路径的项目作为隔离负例。先在「项目长期记忆」确认不同 Provider 的真实项目分组和可追溯知识列表。准备至少三条同项目知识：两条当前有用的、另一条用户明确标记为错误或过时；再准备一个不属于目标项目的 Knowledge ID。

在「工作回顾与 Agent 上下文」下「人工精选 Agent 知识包」仅勾选两条经过人工核对的知识。选择顺序 A、B，生成 Markdown 预览；再次改为 B、A，确保预览中对应知识段落顺序变化、包含两条各自独立 Knowledge ID、来源 Session 和 Provider，不自动加入未选知识。切换 Provider 来源后应该清空此前选中项；超出 30 条的选择被禁用。设置较小 Token 预算，确认超预算文本不会使输出突破约定的保守字符上限，且页面明确标注为估算而非真实 Token 消耗。

负例：直接通过 Tauri API 传入空列表、重复 ID、不同项目知识、归档/已删除知识、错误或过时反馈的知识、另一 Provider 的来源，均应该被 Rust 当前 SQLite 权威校验拒绝。已选知识被重新归组或来源 Session 失效之后，旧前端选择必须失败而不能复用陈旧权限。即使项目知识超过 200 条，未知 ID 不可通过越权提交；UI 必须提示当前只是有界样本，不代表全部项目知识。

完成预览后分别选择「通用 Markdown」、「AGENTS.md 建议片段」、「CLAUDE.md 建议片段」，检查导出是单独建议文件且敏感文本得到合理处理；**绝不自动覆盖或合并真实 AGENTS.md、CLAUDE.md、Provider 原始 Session 或 SiYuan 用户文档**。由用户自行审阅并复制到新 Codex / Claude Code / OpenCode Session，亲自用实际模型确认能复用正确历史；自动化和 Mock 不等于真实模型效果与 Windows 端到端验收。S1.3 完整备份恢复仍在其他模块之后最后完成。

## 来源元数据与上下文注入负例

在隔离环境中构造自定义 Provider 名称/来源范围包含换行、控制字符、伪 Markdown「## 操作指令」、超长字符串或疑似凭据的来源记录。普通项目回顾、完整 Agent 背景以及人工精选 Agent 背景的「来源范围」必须是一行、长度受限，不能把来源标签晋升为新的标题或执行指令；正文依然按现有敏感信息清理和证据引用规则处理。极小预算下应保持输出长度有界；精选条目超预算必须提示失败，而不是静默删除用户勾选的知识。切换 Provider 范围必须同时清除旧预览与旧精选 ID；新范围中的精选请求仍由 Rust 对当前 canonical 项目/Provider 再验证。
