# S3.4 整理知识的持久审核记录、归档与恢复验收

在独立 Windows AIKS 数据目录创建具有不同 Provider 来源的同项目 Knowledge A、B。执行「知识整理 → 多来源合并草稿」，确认草稿前检查来源、模型结果及新增文档标题/正文。确认创建后，验证新的独立 SiYuan 文档可访问，原 A/B 文档未被修改。当前 A、B 的知识详情均应显示同一个「人工审核的知识整理历史」，含新文档 ID、整理方式、全部来源顺序、用户确认时间、当前 active 状态，点击可进入新建文档详情。

完全退出并重新打开 AIKS Desktop 和嵌入式 SiYuan。历史审核记录应依旧从 SQLite 恢复，而非依赖 React 临时的 createdKnowledgeId。使用历史记录的「本地归档」需有明确确认且只更新新建知识的 AIKS 本地状态；源 A/B 和 SiYuan 中仍存在的原始及新建文档不得自动删除。再次重启，历史记录需显示 archived，并能点击「恢复本地知识状态」返回 active。手动删除原始 Knowledge 等故障时，审计关系仍保留，不自动纠正用户编辑。

安全负例：直接调用 `create_organized_knowledge`，传入无来源、重复来源、跨项目来源、compare 仅 1 条来源、非法整理操作或归档来源，必须在 SiYuan 写入前失败，不生成派生文档；普通 `create_knowledge` 无来源参数时仍能正常手工创建。相同 derived ID 不得插入两份审核记录。

远端 HTTP 中断负例：在 SiYuan 文档刚创建成功、SQLite 审计记录提交失败的窗口故障注入，UI 必须明确返回已创建的文档 ID 与**禁止重复点击创建**提示，可从知识列表人工查找。不得向用户声称该异常路径完全实现自动恢复或远端与本地事务原子性。这个实验必须在用户的真实 Windows/SiYuan 环境记录；固定 Rust/TS 测试和 Windows 编译成功不等于真实故障验收通过。S1.3 完整备份恢复仍按要求最后实施。
