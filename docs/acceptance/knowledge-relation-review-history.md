# S2.3 知识关系人工审核历史验收入口

在独立 Windows AIKS 数据目录使用 Codex / Claude Code / OpenCode 的同项目真实 Session，同一知识对建立包含明确原始来源的 `corrects` 或 `supersedes` 关系建议。初始应为 suggested，且「人工审核历史」为空；人工核对两个原文后依次确认、拒绝、再次确认，最终状态应显示 confirmed，但**审计历史应保留之前全部三次真实状态转换**，不能只显示最后一次，重复确认相同状态不新增历史。

知识详情中的「人工审核历史（本地持久记录）」必须展示每一次的 previous_status → next_status、审核时间、关系两端知识 ID，并可跳转到原知识查看；审核时间只代表用户操作时间，不能被当成解决方案生效时间。来源或目标两侧打开都能找到同一条历史；退出 AIKS 重新打开持久 SQLite 后所有审核事件仍在。

负例：提出关系之后将任一源 Session 标记 missing、调整为不同绝对路径项目、或归档 Knowledge，确认必须受拒绝，不能记录伪确认审核；但用户仍能拒绝该错误建议，保留真实拒绝事件。旧的 rejected 关系与其此前确认记录也必须可见，不得从审核历史中隐藏。构造超过 100 次真实转换记录时必须提示「仅展示最近 100 次审核」，不能假称完整历史。旧的 migration 013 应幂等重开，不破坏原始关系与知识。

目前这一入口仅表示**代码级审核可追溯**，用户实际 Windows/SiYuan/真实模型判断仍需集中验收。任何操作都不得修改 Provider 原始文件、静默覆盖 SiYuan 用户编辑或自动删除旧 Knowledge；完整备份 S1.3 仍在其他代码模块全部完成后实施。
