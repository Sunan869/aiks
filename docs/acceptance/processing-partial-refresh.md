# S1.2 处理中心独立刷新与安全重试验收（2026-10-14）

## 场景与不变量

任务列表（最近 200）与全库统计必须来自同一轮成功读取，两者有一处失败则保留上一组完整数据并标注“旧快照”，不允许用新列表配旧统计。同理，流水线记录（最近 300）及统计是另一独立读取组。两组互不拖累：某组不可用时另一组仍正常刷新。最近成功时间必须分别统计，不得把任意一组成功当作全量成功。

当任务组失败时，禁用全局补跑、单条 AI 重试、取消排队和生成新的脱敏预览；曾经审阅过的诊断 JSON 可继续明确作为冻结的旧快照保存/复制，但不可由后台轮询无声更改。原生持久队列负责最终执行条件检查，前端按钮不是业务授权。

任务操作开始及结束均递增一次变更代次，任何与操作重叠的旧轮询均不得重新开启写按钮。对用户展示的刷新与写操作错误必须是固定安全文案，不回显可能包含 Session 正文、路径、API Key 和模型网关地址的传输异常。

历史流水线详情按 run_id 每次独立获取，返回不同 run_id 或无效 session_id、异常/超时、切换路由时旧请求延迟返回，都不得显示旧详情或调用重试。失败时用户可显式重新加载或返回处理中心，不能基于旧行操作。

## 自动化验证与 Windows 人工验收

进入 apps/aiks-desktop 运行 `npm test -- processing-refresh.test.ts processing-detail-refresh.test.ts task-diagnostics-ui.test.ts processing-detail-action.test.ts`，再运行 `npm run build`。通过 CI 检查 UI 契约；Mock 测试仅是行为边界验证，不代表真实 SiYuan/Windows 验收。

在独立 Windows 测试数据目录中人工注入如下情况：仅任务计数失败、仅任务列表失败、仅流水线计数失败、仅流水线记录失败；在长任务操作中强制旧请求延迟返回；在不同流水线详情间快速切换并断开本地后端。每个故障需记录最近成功时间、旧快照提示、操作是否被禁用、任务持久状态，并在恢复后验证操作是否重新开放。保持 Provider 只读与 SiYuan 用户原文冲突保护；不触碰 S1.3 备份。
