# S3.1 本地项目记忆归属修正验收入口

在 Windows 隔离 AIKS 数据目录使用真实 Codex / Claude Code / OpenCode Session。准备一个已确认项目绝对路径的项目 A、一个不同路径项目 B，以及一个缺少路径、此前独立归档的 Session C。进入「项目长期记忆」→「人工修正项目归属」，选择 C、选择项目 A，查看确认提示并人工批准。确认后 A 的 Session 计数、来源集合、Knowledge 证据与按来源/日期报告应包含 C 对应的真实条目，原先独立项目 C 不应重复显示为同项目。同时项目演进关系必须遵守更新后的两端项目约束；不得因为项目名称相同自动合并 B。不要把“用户手工归属”误解为自动验证其事实结论。

对 C 点击「撤销归属修正」，项目 A 计数恢复，C 使用其原始路径/无路径身份单独归档。确认后完全退出 AIKS，重开同一数据目录：原始自动身份及已撤销状态继续保持一致。再次绑定，重启后确认新绑定仍在；检查 SQLite `project_session_binding` 与原始 `source_session.project_path`，后者必须保持 Provider 原始值未变化。重复绑定同一 Session 幂等，非法 Session ID、不存在项目 ID、不具有绝对目录路径的目标项目必须拒绝。

安全与数据边界：UI 仅允许选用本地已存在的真实绝对路径项目，不能输入任意磁盘路径，不能通过任务将目录或 Provider 文件写回；绑定和撤销不得重命名/删除知识，不可覆盖 SiYuan 的人工编辑。Session 选择器最多显示最近 200 条并提醒可能不完整；这是首批可用的人工归属入口，不等同对全量历史 Session 的分页管理。验证与单机离线模式兼容、旧 SQLite 自动升级且重新打开幂等，并记录失败样本。

固定 Mock/SQLite 测试及 Windows Provider GitHub 工作流不能代表 Windows 真机、真实 SiYuan 和模型验收通过。S1.3 全量备份/恢复仍留至其他开发完成后最后实施。


项目名称稳定性负例：把一个较新、源项目显示名与目标项目不同的 Session 归入较旧的真实路径项目；目标项目标题必须仍以其未被手动绑定的真实路径 Session 为准，而不是被迁入 Session 的旧项目名覆盖。迁入后知识数应随 canonical Session ID 所属的归组变化；撤销时标题、计数和知识引用恢复。对应 SQLite/Mock 自动化回归不能代替 Windows 用户目录验证。
