# S2.4 「问 AIKS」来源作用域与引用正确性验收

## 功能与安全边界

在 Desktop「问 AIKS」中，可同时选择「所有项目 / 指定项目」以及「所有来源 / 指定 Provider」。来源列表必须来自本地已发现的项目 Session，而不是固定硬编码；对于仅存在于少量旧 Session 的 Provider，也应显示选项。

普通问答与流式问答应使用相同的 Rust `RagAskRequest` 请求，并且项目/来源均是精确匹配过滤条件。查询命中必须分别约束 Knowledge 来源和 Session 来源，不能从另一个 Provider 泄漏知识证据。改变项目或来源时清空旧对话以避免旧的回答历史混入新的过滤上下文。空字符串保持不限制来源/项目，旧请求中缺失 `source` 也必须兼容。

## 建议的真机回归

在本地隔离数据目录准备同一个项目下分别来自 Codex、Claude Code、OpenCode 的独立知识/原始 Session，包含相同关键词但不同结论。选择某一个 Provider 后检索，应只给出这个来源的证据引用，并支持跳转到正确知识或 Session；选择「所有来源」时恢复原有搜索范围。另以两个同名不同实际目录项目验证已有项目过滤的边界。查询无命中时，应明确说明证据不足，不能让模型凭记忆给出工程结论。

为检查编造引用，可使用**明确隔离的测试模型/代理**返回包含 `[99]`、`[0]` 或没有引用编号的人工测试文本。只有后台真正提供给模型的来源编号才允许显示可点击链接；虚构/缺失编号须出现用户可见的完整性警告，即使同时存在语义检索降级警告，也不能遮盖第二条警告。正确编号不证明事实正确或推理被证据支持，仍需人工核对引用原文。

记录固定样本的 FTS/混合检索命中率、查询 P50/P95、失败与降级路径，以及真实模型生成内容的人工引用核验结果。自动化代码/Mock 和 Windows Desktop 编译成功不能冒充真实模型或真实 Windows+SiYuan 验收。保持 Provider 原文只读，SiYuan 用户编辑冲突不静默覆盖；S1.3 备份/恢复最后实现。

对模型输出的较大数字引用（例如 `[1234]`）也必须执行存在性检查。对无法解析到本地整数的极大编号，应明确显示引用异常提示，不能静默忽略，也不能转成虚假可点击证据。

### 检索后身份变化的故障注入

检索阶段得到候选后，若对应 Knowledge 被归档，或关联 Session 变更来源/项目、被标为缺失，在全文片段加载前必须重新对当前 SQLite 状态执行范围校验，丢弃已经过期的候选；不得把原本仅用于范围 A 的历史命中继续送入模型回答范围 B。新增本地 SQLite 状态变动回归仅验证代码保护，真实并发下的 Windows 故障注入仍需人工完成。

另需验证检索阶段曾命中、但在 RAG 准备读取正文前关联 Knowledge/Session chunk 已被删除或清空的情形：不得再使用搜索阶段缓存的旧 snippet 代替已失效的原始证据。在缺少可读的当前证据时回答应走“依据不足”路径，而不是引用已删除资料。

## S2.4 流式回答完整性与停止状态故障注入（2026-10-12）

使用独立的 Windows AIKS 测试数据目录和可控 OpenAI-compatible 网关，在「问 AIKS」里生成同一个含本地知识引用的回答。先返回规范的 SSE 片段（`data: {"choices":[{"delta":{"content":"..."}}]}`），最后发送 `finish_reason="stop"` 与/或 `data: [DONE]`，验证完整回答显示正常、来源链接仍与后台真实证据匹配。对于不发送 finish_reason 的旧本地网关，应仍可依赖明确的 `[DONE]` 正常完成；仅 HTTP 200 和任意文本片段并不是完整生成的证明。

分别故障注入：已经返回多段文字但网络在 `[DONE]`/stop 之前断开；最后返回 `finish_reason=length`、`content_filter`、`tool_calls`；正常结束之后又返回一段额外文本；SSE 数据行始终不换行并持续膨胀超过 1 MiB。均应得到明确错误而非将已有前缀标成完整回答。对不支持 stream 并返回 `application/json` 的旧网关，`finish_reason=length` 即使正文完整也必须拒绝，`finish_reason=stop` 或缺省字段维持兼容。用多 choice SSE 校验只消费第一条候选，不把不同候选混成一段回答；有些网关在结尾返回 `choices=[]` 的 usage 片段，此时不能将其当作回答正文。

流式文字可能在错误到来前已经临时显示；客户端必须保留并明确呈现失败状态，不能把此类文字或其来源引用视为已验证的最终答复。通过 Rust 固定 SSE 字符串单测，只能证明状态机拒绝这些故障路径，不等于真实网关网络中断、Windows 真机及模型事实正确性已经验收。Provider 只读，SiYuan 原文不会由问答自动覆写；S1.3 完整备份与恢复依旧最后实施。

普通非流式「问 AIKS」也必须验证 `choices[0].finish_reason`：若 HTTP 200 返回内容并同时指示 `length`、`content_filter` 等中断原因，不得把该答案纳入对话完成态。未携带该字段的旧本地模型继续兼容，但必须人工注意可能的不可见截断。

## S2.4 SSE 累计流量与回答资源上限故障注入（2026-10-12）

在隔离的 Windows + 本地 OpenAI-compatible 测试网关中，返回数千条 `data:` 单行不足 1 MiB 的有效 SSE event、空 `choices` usage event，以及 `:` 注释心跳。即使每条数据行合法，累计接收字节超过 16 MiB 时应返回带“safe transport-size limit”的明确失败，而不是把持续出现的心跳当作模型已答完。再持续返回真实 `delta.content`，当累计 UTF-8 正文超过 8 MiB，应在超限的增量文字显示之前出现“safe output-size limit”失败；普通非流式和不支持 SSE 的 `application/json` fallback 也必须拒绝解码后过长的正文。测试含中文文本以及边界值，确认按 UTF-8 字节而非 JavaScript 字符计数，且正常的小型回答、停止原因及来源引用不受影响。

界面可能已经显示被允许的早期临时文字，出现失败后**不得将临时前缀记为回答成功或已核实的引用**。此限制不能替代请求超时、真实 token 管控或对非流式任意超大原始 HTTP body 的网络层截断保护。固定单元测试不等于真实网关、Windows 和模型质量验收。
