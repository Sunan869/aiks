# S3.4 AIKS 自然语言知识整理：行级差异预览验收

以 Windows AIKS 离线版隔离数据目录采集 Codex、Claude Code 与 OpenCode 的同项目知识。打开知识详情 →「受控知识整理」，选择 structure / rewrite / key_conclusions，通过真实模型获取一份尚未确认的整理草稿。页面必须在「当前正文（只读）」与「建议草稿（可编辑）」下显示「整理差异预览（仅供人工核对）」，明确用 + 展示新草稿行、− 展示旧正文中未保留的行、未标识表示一致的行。差异块的文本必须视为数据而不是 HTML/JS 执行。

编辑草稿增加、删除、改写段落，应同步刷新差异展示，并撤销已有人工确认；再次确认前逐条检查知识 ID、事实依据及引用。故意创建包含 Windows CRLF、多字节中文、代码块、长行、含 HTML 标签和 Markdown 伪指令的测试文本：预览不应执行标签/脚本，不能因换行风格变化误报事实改写，超 320 行、64000 字符或 500 展示行时必须出现「差异预览已截断」警告。截断情况下仍应通过两列完整文本及原始 Session 手动核对，不能因为可见差异为零就声称全文没有变化。

多来源 compare、merge_draft 场景必须明确：差异视图默认和当前主知识正文比较，其余来源靠来源 ID、原始文档内容和持久审核记录核对；差异不会代表对全部来源的逐行覆盖和绝对无误差。在用户没有显式勾选确认时，不得写入 SiYuan；确认后必须新建独立知识而不是覆盖源知识、源 Session 或 Provider 原始文件。关闭/重新打开客户端应仍能从 S3.4 持久审核历史查到新副本。

当前 diff 自动化只覆盖纯前端有界算法和 UI 契约，不包含真实模型整理语义保真性或 Windows 用户环境的人工验收记录。全部代码模块完成之后才进行 Windows 集中验收；S1.3 完整备份恢复依然放在其他功能最后。

## 多来源逐项正文核对与二次确认

使用 compare 或 merge_draft，选择同项目的 2～5 条有明确真实 Session 来源的知识。待模型草稿显示后，应该出现「逐一审阅全部来源知识」及各来源的标题和稳定 Knowledge ID。初始只算主知识已查看，只有逐一打开其他来源并查看该来源完整只读正文与草稿的差异，才应允许勾选确认。对于另一个来源，被主知识删除或未出现在主知识的内容未必是草稿新增，因此应在其独立切换视图中再次审核；差异仅是每次与当前选中来源的一对一对照，不能代替语义质量人工判断。

用户修改任何草稿文字后，必须取消之前的确认状态并重新要求打开其他来源；整理方式、来源选择或当前主知识变化时清空旧审核进度和旧来源快照。对直接调用前端 checkpoint 的重复 ID、错序、未经加载、伪造 Knowledge ID 均应拒绝通过。客户端不得仅凭点击次数改变 Rust 的来源校验规则：在用户最终确认新建独立 SiYuan 文档前，仍需实时重新读取所有原来源的完整内容并核对生成时快照，以及由 Rust 强制复查当前 canonical Session 项目路径、活跃状态与所有来源身份。

此审核入口是可操作的「逐份查看」辅助，不能证明模型对 5 份材料的每个事实都准确。超长文本的截断差异需查看原始完整正文；Provider 只读、SiYuan 用户编辑不覆盖、S1.3 最后实施约束不变。
