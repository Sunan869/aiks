
# S3.1 项目知识复核队列：过时和矛盾线索的人工审核入口

以独立 Windows AIKS 数据目录使用真实 Codex / Claude Code / OpenCode 的 Session。在三个 Provider 具有同一经验证真实项目路径的知识中，分别人工标记 incorrect、outdated、duplicate、needs_detail，再建立带来源的 corrects/supersedes 待确认关系和一条人工确认 resolved_by 关系，并拒绝另一条建议。准备一个「同显示名但不同实际路径」的隔离项目作为负例。

打开「项目长期记忆 → 项目知识复核队列（明确证据）」，分别切换「所有线索 / 用户质量反馈 / 人工关系线索」。每条线索应可打开相关 Knowledge 及其原始 Session，展示已有反馈或关系审核依据，并明确区分待审核、已有人工确认两种关系；任何状态都不证明该工程事实已被客观验证。仅 suggested 建议可以通过已有的人类审阅、显式确认入口进入 confirmed。被拒绝或已迁走的旧关系不得被伪装成已确认的风险事实。

在两个项目间快速切换并故意延迟异步关系读取：前一个项目的旧结果不得显示在新项目上。将某端 Knowledge 归档或把来源 Session 标记 missing 后，该关系应从当前有效项目证据列表中消失，同时已有审核历史仍可从关系审核记录查询。让项目知识样本超过 200、关系超过 100、联合队列超过 100，检查范围不完整/截断提示；空队列不得报告「项目无风险」。

此模块不自动检测语义矛盾、替人决定技术方案是否过时、修改 Provider 文件、写入 SiYuan 或删除旧知识。CI/Rust/Mock 不代表 Windows 真机和真实模型事实准确率验收通过。最后才实施 S1.3 完整备份与恢复。
