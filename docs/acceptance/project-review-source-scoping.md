# S3.2/S3.3 项目来源范围导出验收

在「项目长期记忆」里选择有多来源会话的同一项目，在工作回顾/Agent 上下文区域选择「全部来源」或某一个具体 Provider。生成的 Markdown 明确显示来源范围；按 A 来源导出不得出现 B 来源的唯一知识内容或 Session 引用，切换成 B 同理。

筛选在 Rust 后端生成前执行，而不是事后从 Markdown 移除文本。未知来源参数应直接拒绝；省略来源参数保持历史 API 的全来源行为。切换来源时应废弃尚未返回的旧请求并清除旧预览。

即使导出选中了单个来源，若当前项目的知识快照此前已达到 200 条截断上限，报告仍需提示不是完整历史。导出必须经人工预览再复制或保存，不得自动写 Provider、现有 Agent 指令文件或 SiYuan 原文。CI/Mock 不能代替 Windows + 真实内嵌 SiYuan 多来源验证。

来源选择必须在 SQL 读取阶段、**截断之前**应用，而不能先读取全项目最近 200 条再过滤，否则低频来源的历史会被漏掉。每个来源单独最多读取 200 条，只有该来源超过上限时才标记截断；未选来源则保持全来源上限。日期范围仍为渲染筛选，有界结果并不保证覆盖全部历史，须在真实环境核对。
