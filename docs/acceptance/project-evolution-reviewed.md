# S3.1 项目知识演进：人工审核关系验收

在 Windows 本地隔离 AIKS 数据目录采集 Codex、Claude Code 与 OpenCode 真实 Session。选取两条确实属于**同一绝对路径项目**的知识，在知识详情中通过现有关系入口提交 `corrects`、`supersedes` 或 `resolved_by`，提供可追溯的原始 Session/知识证据，人工确认一条关系，另一条保持 suggested。

在「项目长期记忆」→「知识演进与已审核的修正关系」核查：待审核关系明确显示不能视为生效结论；已确认关系有不同标识；两端知识分别可打开详情；显示现有审核证据，不推断事实、写作模型结论或虚构生效时间。用户确认或拒绝后重新打开项目，应反映审核结果，且不得更改原 Knowledge/Session 文本。

故障注入：准备同名但不同真实目录的另一个项目，在 SQLite 受控测试中放入跨项目旧关系。旧关系不应混入当前项目；来源 Session 被标记缺失、被改为另一个项目路径或关系涉及 archived Knowledge 时不再显示。不展示 rejected 关系，亦不因为关联合规而自动判断任一知识真实或过时。超过 100 条时提示结果截断；切换项目时旧异步响应不得覆盖新项目。

此项仅提供人工有据可查的项目演进记录，不会修改 Provider 文件、自动编辑 SiYuan 文档、隐藏用户原文、自动确认建议关系或合并不同路径项目。CI/Mock 不等于真实 Windows/SiYuan 端到端验收。S1.3 完整备份/恢复仍最后开发。

## 项目记忆页直接审核与切换隔离

对于 suggested 的关系，用户应能在打开两端知识详情核对原文后点击「核对原文后确认关系」或「拒绝关系建议」，必须出现操作确认对话框。确认后状态显示「用户已确认关系」，拒绝后列表不再显示，但原有知识、Session 和关系审核历史仍保存。提交时双击不得创建重复审核，提交中切换项目不会把旧项目关系结果显示到新项目。任何网络/SQLite 写入失败应明确显示错误，不能假装审核成功。
