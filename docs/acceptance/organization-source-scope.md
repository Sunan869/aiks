# S3.4 受控多来源整理：权威项目归属与来源隔离验收

准备真实、已同步到 AIKS 的 Codex 项目 A `C:/work/a`、Claude Code 项目 B `D:/work/a`，两个项目刻意使用相同显示名；再准备 OpenCode 项目 C，它的已确认真实路径与 A 相同。在知识详情选择 `compare` 或 `merge_draft`：

- A + B：即便显示名称一致，后端必须在调用模型前拒绝，且不应创建新知识，也不得向模型传输该混合上下文。
- A + C：如果后端真实路径身份一致、知识都处于 active、Session 未缺失，则允许继续进入**草稿预览**，但不能未经用户确认自行创建知识。
- 提交草稿之后，尝试在审核期间将来源 Knowledge 归档、把 Session 标记为缺失或修改项目路径/人工绑定关系。用户点击确认新建前，须再次查询当前 SQLite 范围并拒绝过期来源；保留之前已有的内容哈希/元数据快照复核。
- 单条人工知识可独立整理，但两条没有可验证 Session 项目身份的人工知识不能被自动认定同项目。拒绝结果必须显示明确错误，不得默默跳过或自动强行合并。用户显式重新选择来源后可重试。

模型是否得到准确方案、真实模型前后的响应质量与 Windows 本地 SQLite/SiYuan 并发时序仍需真实验收记录；Core SQLite 单测/前端 Mock/Windows 编译都不能代替它们。Provider 原文件、原 Session 的 `project_path`、SiYuan 人工修改、既有 Knowledge 均不可被此流程自动覆盖。完整备份与恢复 S1.3 最后实现。

## 最终写入命令门禁（不可只依赖 UI 校验）

在同名不同路径项目 A/B 的负例中，即使模拟前端跳过前两次 `validate_organization_scope` 调用，最终的 `create_organized_knowledge` 写入命令也必须重新从 SQLite 校验必选的来源知识 ID，并且**在开始任何 SiYuan 创建请求前**拒绝。缺少来源 ID、来源不存在/归档、跨项目、Session 缺失时不能落库，也不能向 SiYuan 发布未确认的合并文档。正常两个真实同路径/已人工修正到同项目的来源，经过审阅后则应可创建新的独立知识，来源不被修改。

原 `create_knowledge` 手工新建接口必须保持向后兼容，不得无端拒绝没有来源 ID 的正常手工文档。测试确认新建整理草稿仍由用户主动点击；归档/恢复只涉及新建知识在 AIKS 本地的状态，SiYuan 中旧用户编辑不自动覆盖。

由于命令内部仍会通过异步 HTTP 操作访问 SiYuan，本次代码检查并非远端创建事务的原子性证明；真实断网、超时和版本冲突必须在 Windows 真机验收中分别记录。
