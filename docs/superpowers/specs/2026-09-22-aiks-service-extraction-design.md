# AIKS 独立服务化设计：同一服务，本地与团队两种部署

日期：2026-09-22
分支：`feature/aiks-service-extraction`
基线：从 `main` 的 `e0f2d8a28938b3f0e4bcc64cec11a1b42ae2e740` 新建，不从此前功能分支继续叠加。
状态：用户已确认架构方向与启动本分支；本文为待书面审阅的设计稿。本提交仅包含设计，不包含可运行的 AIKS Service、权限实现或测试通过声明。`main` 不变，不合并、不发布安装包。

## 1. 已确认目标

用户要求将当前耦合在桌面端的业务能力抽成独立 AIKS Service。同一套 Service 与思源部署在本机时是完整个人版，部署在远程时提供团队/公司能力；客户端通过同一业务 API 使用两种部署。

必须保留：

- 完整本地个人版，无需用户另搭服务器、注册团队账户或安装 Docker；离线资源预置后可以断网启动。
- 已集成的 AI 工具与现有会话、知识、搜索回归；不重写解析器，不清空已有数据库。
- 团队个人私有、项目共享、部门共享；本地私有资料不因登录公司或切换服务地址自动上传。
- 知识库问答进入 Service/Core，不建立另一套只在桌面端可用的检索和 AI 流程。
- **服务端思源不直接开放给普通用户。普通用户仅通过经过认证和授权的 AIKS 业务接口读写，不获得思源管理员 Token，不开放任意思源接口代理。**

“完全离线”包含本地模型、思源资源和运行依赖预置；调用云端模型不属于完全离线。没有本地模型时，采集、浏览、编辑与关键词搜索仍可用，AI 功能明确显示未配置，不自动回退外部模型。

## 3. 方案选择

选择：**同一独立服务程序 + 同一业务 API + 可替换运行配置**。首期是一个模块化单体进程，不拆微服务。

不选择“本地业务继续散落 Tauri，远程再写一个后端”：会增加两套路径的行为漂移和重复修复。

不选择“将全部 Tauri Command 原样暴露成 HTTP”：目录选择、文件系统、进程管理和通用思源操作不能成为远程用户能力。

保留 `aiks-core` 作为共享内部库，新增 `apps/aiks-service` 作为无 Tauri 依赖的可执行入口。是否新增小型协议 crate，由实施计划按依赖关系决定；不为了目录美观立即搬空整个 Core。

### 部署形态

个人：Desktop/采集器 → loopback AIKS Service → 本机 StateDb、思源与可选本机模型。

团队：Desktop/采集器或浏览器 → HTTPS AIKS Service → 内部业务库、内部思源与允许的模型服务。

两者的业务请求、快照、处理状态和错误契约一致；本地子进程生命周期接口不属于远程业务 API。

服务化完成但多人授权未完成的构建只允许本机单用户验证，不得作为团队服务开放。不能把改监听地址当成启用团队权限。

## 4. 职责与配置归属

### 客户端

保留工具目录发现、只读 Provider 解析、采集游标、受控脱敏/排除、共享选择、本地待上传队列与重试。保留窗口、托盘、目录选择、系统通知和本机子进程管理。

不再直接改业务 StateDb、启动第二个 PipelineWorker 或对同一批共享数据自行再提炼。客户端日志不输出会话正文、Token 或敏感完整路径。

### AIKS Service

负责会话接收与快照、身份/空间授权、知识业务、任务队列、模型配置、索引/搜索、问答、思源内容适配、文档事件、审计和状态接口。服务不依赖 AppHandle、Webview、Tauri IPC 或用户电脑文件存在。

Service 必须能在没有图形桌面、没有任何 AI 工具安装的机器上消费已接收快照。

### 数据与模型配置

采集目录、设备凭据、上传队列与服务连接记录属于客户端；模型凭据、内容服务内部地址、团队策略和业务数据库属于 Service。普通用户响应不得包含思源地址/Token、模型 Secret 或服务器文件路径。

本地与远程连接配置以持久 `service_instance_id` 区分；端口和 URL 不是数据身份。切换连接不能改写旧 outbox 的目标。连接变化不触发数据迁移或自动全量上传。

本地和远程 Service 可以共存，但第一版按空间/连接分别访问，不默认做跨服务联合检索或全量双向同步。

## 5. 接收快照与任务可靠性

### 接收契约

客户端上传统一会话内容、协议版本、来源 key、已登记的来源实例身份、上游会话 ID、提交 ID、目标空间、版本/摘要及完整性信息。外部目录路径最多作为受控来源描述，不用于让 Service 打开文件。

服务从认证凭据确定提交者/设备及可写空间，不信任请求正文自报的 user_id、owner_id、角色或权限。来源名字、source path、同名项目均不能确定成员关系。

为来源实例建立稳定命名空间。重复提交的幂等范围包含服务、授权主体、来源实例、上游会话和目标空间；跨用户/跨空间不做会泄露存在性的自动内容归并。不同设备的同一历史只有显式映射到同一来源实例后才合并。

### 持久化与执行

1. 校验权限、协议、数量/字节预算、结构和摘要；将接受的快照保存为不可变版本。
2. 在持久事务中记录快照身份、当前版本和待处理任务；成功响应表示已持久接收，不表示提炼成功。
3. Worker 只读取绑定的快照版本；任务重试与服务重启不再访问客户端 Provider。
4. 老版本/延迟上传不覆盖新版本；同一提交 ID 携带不同内容必须冲突报错。
5. 新版本到来后，旧任务结果不得覆盖当前知识/索引。使用版本或 generation 条件提交，保持现有任务恢复语义。
6. 半写/不完整会话不得静默覆盖上次完整快照；明确返回可重试状态。删除来源目录、停用采集器或扫描失败不是删除业务知识的授权。

接收响应应包含 receipt、session/revision/job 身份和实际状态。后台错误通过任务接口/进度事件返回，不能伪装成空结果或成功。

上传优先采用有界完整会话快照以降低一致性风险；传输分片不改变提交原子性。增量消息 patch 协议不作为第一批前置。

附件仅处理显式允许、独立上传并授权的资产；不跟随正文中的路径/URL读取任意客户端或服务器文件。

## 6. 业务 API 与空间模型

API 使用版本化前缀（拟 `/api/v1`），包括身份/当前能力、空间、会话接收/查询、任务、知识/内容、搜索、AI Assist、问答和进度。详细 route/DTO 在实施计划中定义，不在本稿虚报接口已存在。

`GET /healthz` 仅返回无敏感数据的存活状态；数据库、思源和模型 readiness 分开。依赖失败不阻断无关基础功能，模型未配置不是整个服务死亡。

本地模式经过受控启动握手产生本地用户和本地个人空间，不显示团队登录界面；不是绕过所有授权。团队请求从有效会话/设备令牌解析主体；每个业务操作使用主体、空间与权限版本上下文。

空间类型：个人私有、项目共享、部门共享。角色先采用查看者、编辑者、空间管理者；平台运维管理与个人内容读取权限分离。服务器个人空间仅承诺应用权限隔离，不承诺服务器管理员无法读取磁盘或端到端加密。

授权在服务端默认拒绝，覆盖列表、计数、详情、创建、编辑、删除、导出、资产、引用/反链、任务、搜索、问答和事件订阅。未知/无权资源采用一致的错误策略，不通过标题、摘要、统计或命中数量泄露。

搜索在授权范围内召回并在正文读取时再次校验；不把无权结果返回前端再隐藏。权限修改要使相关缓存和后续事件失效，任务执行/发布也校验当前策略。

首期单公司部署，项目可跨部门授权；组织大树继承、任意块级 ACL、多租户 SaaS、SSO 等扩展不进入首批服务抽离。

## 7. 思源作为内部内容服务：硬性安全边界

### 网络与凭据

远程思源只绑定受控内部网络或本机回环；容器部署不映射思源端口到普通用户可达网络。不使用 host network 绕过隔离。反向代理只公开 AIKS 的受控入口，思源维护入口仅经运维私网访问。

只有服务进程持有思源凭据。API响应、前端配置、重定向、错误、日志、静态资源、cookie 和 WebSocket 地址都不得泄露或下发该凭据。

### 禁止通用代理

不提供 `/proxy/*`、原样转发 `/api/*`、任意 SQL、文件路径访问、任意上游 URL 或任意思源方法/路径调用。隐藏端口后再加一层无校验透明代理不满足要求。

Service 暴露“读取授权文档”“更新授权正文”“上传/读取授权资产”等有类型的业务动作。上游地址固定于管理员配置，不从普通请求决定；拒绝上游任意重定向，不把用户提供的会话/正文 URL当成授权下载地址。

对块、文档、附件分别解析服务端映射，验证其实际归属空间。仅检查客户端给出的 doc_id 而不验证 block_id/asset_id 不合格。路径规范化和资源归属检查在服务端执行。

原始思源 API 仅由内部适配器使用，仍遵守现有“只通过公开 HTTP API，不直接修改 .sy 或思源 SQLite”的仓库约束。

### 工作台的兼容边界

不能直接加载服务端原生思源页面并给它全库凭据，再声称实现了个人/项目隔离。现有工作台需要把业务调用收口到受控内容接口；Tauri 内窗口动作可保留本地实现。

团队第一版交付经授权的文档浏览/编辑与引用定位。未经适配的原生 SQL 查询、全库搜索、图谱、插件、同步、全库导出等入口不开放；不承诺未经验证的全部思源原生 UI 即插即用。后续逐项增加白名单能力，不能用任意代理换兼容性。

过渡期间本地单用户旧工作台可暂留回滚路径，但最终业务处理仍走 Service。团队模式必须在受控内容链路通过测试后才可启用；若 UI 无法安全适配，保持团队能力关闭，不降低隔离要求。

## 8. 文档权威、事件与跨系统一致性

思源管理已发布文档的权威正文/结构；AIKS 管理会话快照、知识身份/权限、任务、索引和审计。索引是可重建派生数据，不把思源当成全部业务状态的替代品。

Service 发起文档写入前记录持久意图，使用幂等操作 ID、内容基线和版本校验；成功后更新映射并投递持久索引事件。思源与业务库不在一个事务里，失败用可重试 outbox/对账恢复，不用“调用成功后随手改状态”掩盖中间崩溃。

用户直接编辑造成基线变化必须冲突处理，不能静默覆盖。超时后重试创建前核查操作映射，避免重复远端文档。

索引事件不再依赖某个员工的 Desktop/Tauri 窗口。通过 Service 写入的事件直接持久化；允许的运维编辑通过受控内部事件或周期对账补偿，事件只作为变化提示，正文由 Service 从固定内容服务获取。

事件按内容版本去重；服务重启/断线后可恢复。过时事件不复活已删除数据。快照/正文版本和索引版本可诊断，搜索明确标识过期或降级，不能读取缓存绕过权限。

## 9. 本地进程、安全与离线体验

同一 Service 编译为各目标平台可执行文件。桌面个人安装包包含 Service 和思源运行资源，由受控本机进程管理器启动并等待健康检查；不要求普通个人用户手动运行 Docker/systemd。

个人模式仅监听 loopback；本地 API 仍需随机启动凭据/握手，限制 Host、Origin、CORS 和请求体，防止任意网页利用本地服务。禁止通配跨域 + 凭据组合。本机传输不能接受团队用户伪造的转发头来获得本地身份。

密钥不出现在 URL、命令行日志或可读配置输出中。子进程启动参数固定/校验，前端不得执行任意命令。

Desktop 只关闭由自己创建且验证身份的本机子进程，连接远程时不控制服务器生命周期。端口被占用时不得盲信该端口上的未知服务。多个 Desktop 启动不能并行启动两个写相同业务库的服务。

退到托盘和彻底退出行为分别定义；崩溃采用有界重启、退避、任务恢复和诊断，不无限重启。本机未启动模型时非 AI 功能可用。

模型文件、思源资源、前端资源提前准备；断网验收包含启动、采集、编辑、关键词搜索和本机模型问答，不只测试“没有团队服务器”。未配置本地模型时禁止暗中请求云端。

## 10. 本地与共享的数据流

本地私有不等于服务器个人私有。前者不上传；后者对应用中的其它用户不可见，但已位于服务器。

第一次登录公司只创建/连接对应空间，不移动历史数据。共享是显式发布：选择目标项目/部门，确认内容及来源/附件披露范围，再创建目标副本与关联版本。

共享知识不得隐式携带私有会话全文、附件、反链或能绕过授权的来源链接。混合资料生成的回答默认保留在请求者私有范围；发布到共享空间需要独立确认与披露检查。

第一版不做整库双向同步、多用户离线编辑自动合并、共享库自动全量缓存或跨服务自动合并问答。断线时本地功能继续，远程请求明确失败/重试；outbox 只发送已授权给原目标的内容。

撤销权限阻止后续服务访问，并清理受控缓存，但不承诺收回用户已经自行导出的数据。

## 11. 存储、升级与并发

首期保留 SQLite 和现有正式 migration，运行单个业务 Service 写入者。不得把业务 SQLite 放到客户端共享网络目录，也不宣称已有多实例水平扩容。

新表通过后续正式 migration 增加：服务实例/空间主体、来源登记、不可变会话快照、上传幂等/receipt、持久内容事件和授权关联。具体字段与索引需在实施计划中定义；不要原地改已发布 migrations。

通过最小存储/快照访问边界解除 Tauri/Provider 耦合，不为抽象而先重写所有 Repo。以后切 PostgreSQL 或独立向量库是独立迁移任务，不能以换连接串宣称兼容。

旧个人库迁移到默认本地用户/空间，保留已有 session/knowledge ID、source key、思源映射和内容基线。迁移运行前停止旧 Worker/引擎，备份数据库与对应思源数据，避免双写。

本地迁远程是显式备份/导入流程，需要快照、资产、映射和版本校验；不是切换 URL。首期不自动运行迁移，不要求用户清空个人库。

## 12. 问答能力放置

RAG 属于 Service 的业务模块，复用现有 ModelService 与 UnifiedSearch；不在 Desktop/思源再建另一套模型后端。

默认优先已整理知识，可显式纳入有权会话。检索资料当作不可信参考内容，不能把资料里的命令当成服务指令。没有依据时明确说明不足，冲突材料保留出处。

回答与引用绑定空间、文档/块和版本；在召回、取正文、发送模型、返回引用及后续追问时维持授权边界。缓存按实例、主体/权限和资料版本隔离。

本地空间不默认送公司模型。生成答案不是发布知识，写入共享空间是独立受控动作。首批服务抽离先保留现有搜索/AI Assist；完整问答作为后续里程碑，不能以一个聊天框宣布完成。

## 13. 分段交付与验收出口

### S1：独立业务服务，先守住个人版

新增无 Tauri 服务入口、版本化 API 和本机安全握手；完成快照接收/持久化/队列读取，搜索与知识业务复用 Core。Desktop 首条接收与查询链路改走本机 HTTP，旧路径仅用于受控回滚。

必须证明：没有员工目录的服务也能处理已接收会话；客户端退出不影响任务；离线个人数据不丢失；不会同时启动两套 Worker。S1 未完成团队授权时仅允许本机单用户，不公开远程端口。

### S2：团队空间与内部思源内容接口

实现单公司账户/成员、服务器个人私有/项目/部门空间、角色和显式共享。接入受控文档读写/资产/引用，落实网络隔离、每次授权、索引事件、权限撤销与审计。通过之前禁止普通用户访问团队部署。

必须证明：甲的私有正文/标题/资产/任务/搜索/引用对乙不可见；无权限请求在发起思源调用前被拒绝；不同入口和事件订阅不能绕过权限。

### S3：本地打包、远程部署、工作台迁移

同一业务 API 完成桌面业务路径切换和两种部署测试。提供本机随包启动与服务器部署说明；服务端只公开 AIKS入口，工作台只用受控内容接口。完成旧库升级/备份恢复验证，不将尚未通过适配的思源 UI 功能开放给普通用户。

### S4：两种部署共用知识问答

完成带授权、引用、追问和模型降级的问答流程，本机模型离线验收与团队泄露回归分别运行。不影响之前已接入的来源与搜索性能修复。

分段用于控制风险，不取消最终团队/离线目标。每个里程碑汇报实际代码与测试，不把设计、stub、mock、仅 healthz 或仅编译通过当作完整功能交付。

## 14. 必测用例与交付门槛

- 相同规范会话经本地 HTTP 和远程测试 HTTP 走同一处理链路；现有 16 个本地 Provider 及网页缓存来源回归继续通过。
- 客户端确认前断线、重复上传、同 key 不同内容、乱序版本、超限/半写输入、服务重启和旧任务晚完成。
- 空/错误认证、本地伪造 Host/Origin、跨空间枚举、伪造 owner、块/附件归属不匹配、批量查询/导出/事件流越权。
- 未授权内容不会进入模型请求、搜索摘要、统计、回答缓存、引用或跨用户日志；成员撤销后新请求和订阅不能继续取得内容。
- 服务侧思源无公网/普通用户端口；不存在 raw API/SQL/file/任意URL代理；模型/思源 Token 不出现在客户端响应与打包前端。
- 思源超时/离线、数据库失败、模型禁用/超时分别降级，必需阶段失败不能写成功状态；内容事件重试不会重复建文档。
- 旧库升级保留 ID、知识、来源与思源映射；中断迁移与备份恢复有验证；不能让测试依赖真实用户模型或私密会话。
- 断网从安装资源启动、采集、阅读编辑、关键词搜索；有本机模型时提炼/语义检索/问答，无本机模型时清晰降级。
- 同一版本的 Service、Desktop、协议不匹配时给出明确兼容错误；关闭客户端不关闭远程服务；端口占用不连接陌生服务。
- 按实际变更执行 Core/CLI、完整 workspace、前端、Windows 与部署/网络边界测试；真实安装和大库性能另行记录，不用 CI 代替。
