# AIKS S2：钉钉登录与单公司知识共享设计

日期：2026-09-23
代码基线：feature/aiks-service-extraction / 5b521dc77734500ac9758247c561467a850670e2
状态：用户已同意业务方向；本文件为待审阅设计，不代表团队功能已经实现或开放。

## 1. 已确认的目标

把同一套 AIKS Core / Service 扩展为单公司部署的知识共享版，保留完整个人离线模式。用户通过钉钉登录团队服务；知识默认私有，可以同时分享给指定人员、指定组织节点。第一版只有创建者可以修改正文、管理分享和归档；被分享者只读。不做多人实时编辑、自动合并、跨企业分享、匿名链接和多租户 SaaS。

个人版继续使用本机 Service / 思源 / 数据目录，不需要钉钉登录，不因团队功能上线而自动迁移或上传任何个人资料。完全离线 AI 仍要求本机模型与运行资源已准备好。首次引导可跳过、扫描与同步分离、会话排除不要求用户知道 ID 等现有体验保持。

## 2. 基线事实与改造边界

已核对的代码：
- apps/aiks-service/src/config.rs 目前只允许 personal 模式和数字回环监听，不能直接修改监听地址就视为团队版。
- crates/aiks-core/src/service/runtime.rs 目前从 store.local_context() 获得单用户上下文；团队请求必须改为经过服务端认证的请求上下文，不能继续复用固定本地身份。
- AGENTS.md 明确 Core 为唯一业务实现，思源是内部内容服务，Provider 只在员工客户端读取本机允许的会话数据；这些边界继续成立。

S2 采用同一服务程序的显式团队运行模式和同一桌面程序的可选团队连接。不复制另一套 Pipeline、Knowledge、Search。个人回环认证与团队认证分开，个人模式原有拒绝外部访问的测试保留。S2 授权、连接与部署验收通过之前不得放开团队监听。

## 3. 钉钉应用选择与外部依赖

一套服务绑定一个明确的公司 CorpId。创建该组织的“企业内部应用 / 钉钉应用”，不是面向多个企业分发的第三方企业应用。“第三方登录”描述 AIKS 借助钉钉认证，不表示应用类别必须选择“第三方企业应用”。

新后台按应用添加能力；网页应用/H5 是可选工作台入口能力，不要求重写 AIKS 为钉钉小程序。本期主要使用浏览器授权登录与组织通讯录只读接口，不申请机器人、通讯录写入、审批、群聊记录、手机号或邮箱等无关权限。

需要运维提供的配置：
- 企业 CorpId；应用 Client ID（企业内部应用原称 AppKey）；Client Secret（原称 AppSecret）。
- AIKS 团队服务的固定 HTTPS origin 与 OAuth 回调完整 URL。
- 通讯录只读授权范围；初期可限测试人员/部门。范围外人员和部门不显示，不将不完整目录标记为完整公司目录。
- 按钉钉控制台实际要求设置服务端出口 IP 白名单、应用可见范围和授权审批。

Client Secret 仅放服务端环境变量或挂载的秘密文件，禁止进入 Git、桌面安装包、Webview、日志和示例明文。AgentId 仅在增加钉钉工作台入口等能力时按需记录，不作为登录唯一身份。

拟定回调路径：/api/v1/auth/dingtalk/callback。它属于 AIKS，不属于思源；最终 origin 由部署者配置。页面中的“重定向URL/回调地址”必须与实际 OAuth redirect_uri 匹配，不能填写 Vite 开发端口或思源 6806 地址代替。

## 4. 登录、身份映射与退出

拟定桌面登录流程：
1. 用户显式添加/选择团队服务，客户端使用已确认的 HTTPS origin 建立短期登录事务；启动系统浏览器，不把企业秘密放在桌面。
2. AIKS 服务建立一次性的 OAuth state，绑定浏览器授权事务和发起客户端。浏览器访问钉钉授权页。
3. 回调由 AIKS 服务消费 authCode 和 state。严格验证 state 的有效期、一次性和绑定关系；拒绝重放、开放重定向、来源替换。
4. 服务端向钉钉兑换用户访问凭证，读取身份，并用应用授权确认该用户属于配置的 CorpId、处于有效成员状态及允许访问范围。不能仅相信客户端传入的 corpId/userId，也不能仅凭昵称/手机号合并用户。
5. 使用独立 AIKS user_id 作为所有权标识，外部身份映射按身份提供方、公司与稳定外部标识唯一化。UnionId、组织内 UserId 的用途分开，不把它们互换。
6. 客户端通过 HTTPS 和仅本客户端持有的高熵一次性验证信息完成登录结果交换。URL、二维码、浏览器 localStorage 不携带 AIKS 长期凭据；客户端凭据保存在原生安全存储。
7. AIKS 自己管理会话有效期、续期、撤销、退出和设备绑定；钉钉用户令牌不是直接通行整个 AIKS 的业务令牌。只在必要时保留第三方刷新凭据，持久化必须保护。

以上桌面交接是 AIKS 自身协议设计，不能假定钉钉支持某个未经核对的 PKCE/device-code 扩展。OAuth 与成员映射的具体 API/权限须在实现时按官方文档逐项核对，并用合成响应测试。组织不匹配、取消授权、缺权限、网络错误均明确失败，不回退本地用户或管理员。

个人模式不经过该流程。退出团队只撤销当前团队会话；不杀远程进程，不删除本地资料，不把队列转投其他用户或服务。

## 5. 组织目录及成员有效性

只同步已授权范围内的部门、基本人员信息和人员-部门关系。不写钉钉通讯录。部门选择是具体稳定节点 ID，而不是“所有第 N 级部门”。内部 UI 使用可识别的姓名/部门路径，内部标识由程序管理。

授权计算支持一人多个部门。选择组织时默认仅该节点直接成员；“包含下级部门”显式勾选，不能由上级身份推导其自动拥有下级私有文档。

建议第一版采用分页完整同步 + 登录时成员校验 + 管理员手动刷新；事件订阅可后续加速，但不是正确性唯一来源。目录同步记录 generation、授权范围、完成状态、最近成功时间。只在一个范围的完整分页结果校验成功后整体发布新快照；超时/部分结果不得把未扫描成员批量判为离职。部门环、自引用、重复/缺失身份按错误处理。

初始安全默认建议：每 5 分钟尝试刷新；目录授权信息最长使用 15 分钟，超时拒绝基于陈旧组织信息的团队授权并提示目录暂不可用，不退回全员权限。该数值是本设计建议，不是钉钉能力承诺；实施计划需补齐测试和运维配置。已收到停用/离职事实时立即撤销该主体的团队会话；调出部门后撤销该部门通路，仍有直接分享时按并集保留。移出应用允许范围也停止团队访问。

管理员只能管理目录同步和服务配置，不因此默认读取每个人私有知识。创建者离职后文档不自动变成其他员工所有；只读授权是否继续可用由保留策略决定，默认保留现有文档和授权，不开放编辑。所有权移交作为单独显式流程，不在首版自动执行。

## 6. 最小权限模型

不建立复杂角色模板或单独部门工作区复制正文。团队资源具有 company_id、owner_user_id 和文档级 grant；UI 的“我的知识、分享给我的、部门共享”是查看入口，不是三套正文。

建议新增概念（最终迁移编号/字段由实施计划确认）：
- identity_provider_binding：本地 user_id 与第三方稳定身份/公司绑定。
- team_user / org_unit / org_membership：有效主体与发布后的组织快照。
- resource_ownership：知识、会话及附件映射到可信所有者；未知旧数据不猜所有者。
- document_share_grant：document_id + target_type(user/org) + target_id + include_descendants + permission(read) + grant_version。
- auth_session / login_attempt：会话、撤销与短期登录事务。
- audit_event：分享、撤销、正文修改、授权失败和组织同步的必要记录，不保存正文/秘密。

鉴权原则：默认拒绝；只有同公司有效成员可参与授权。文档所有者可以读写/管理分享；明确人员授权或部门成员授权可读。人员授权和部门授权可组合，取并集；不实现 deny 规则、隐式领导权限、组织等级特殊优先级。

S2 首版 permission 只接受 read。“可编辑”作为未来枚举扩展，不显示为可用选项，不接收 write/edit 后又静默降级成 read。只有创建者可修改这一规则在服务端执行。

分享原地生效，不复制团队已存正文。撤销阻止后续读取和索引召回，并使相关缓存失效；无法收回用户已下载、截图或复制的内容，不承诺远程擦除。

## 7. 分享对象与资料泄漏边界

默认会话、提炼草稿、知识均归真实用户私有；后台 Worker 不成为所有者。分享知识不隐式分享整段原始 AI 会话、处理日志、来源路径或模型提示。共享文档中的源会话链接需独立鉴权，无权时不返回源标题/正文。

只分享这篇文档自身拥有并受控存储的附件。引用另一个私有文档、另一个文档的附件、任意 URL 或文件路径，不因出现在正文中就自动获得访问权。无法证明归属的附件不可公开读取；不得返回通用思源文件路径接口。

个人电脑上的知识发布到团队是显式上传，目标服务、公司、当前用户、空间和内容版本固定；登录公司或更改连接不触发整库上传，不把本地所有者 ID 当成公司的有效主体。发布后的团队文档默认私有，随后可在分享框中增加授权。

## 8. 检索、读取与受控编辑

授权必须进入 Core 的查询路径：列表、统计、搜索候选 LIMIT 前、关键词与语义降级路径都使用同一可信上下文。正文、文档块、附件、回执、任务与引用再次检查。用户不能提交任意 owner/principal 来替换服务端身份。

当前 local_context 路径保留为 personal 适配器；团队 runtime 的公开操作接收服务端认证后的上下文。不能先调个人全库搜索，再在前端或最终结果里过滤。

已发布正文仍从思源规范 API 获取，草稿明确标注。思源不可用报告 content_unavailable，不能用 SQLite 投影冒充当前正文。网络等待前后检查可见性及相关授权/内容版本，不跨网络等待持有 SQLite 锁。

首版增加创建者受控编辑/发布的必要接口，不直接开放思源编辑器或 proxy/SQL/file 透传。编辑保存带 base_revision/ETag；同一创建者两个窗口也不能静默覆盖。无需 OT/CRDT、实时光标或自动合并。

思源写入与业务 SQLite 不是同一事务：使用持久写入意图、每文档串行化和规范正文基线核对；网络超时先协调已发生的写入，不盲目重试创建。提交后才标记新内容版本并刷新索引；失败时显示待恢复/冲突，而非伪成功。AI 重新提炼保留用户编辑，自动结果不覆盖已发布的人工作品。

## 9. 部署与运行边界

首版单公司、单个 AIKS Service 写入实例，先复用现有 SQLite/持久任务，不同时引入微服务与数据库替换。容量和响应时间必须实测，单实例方案不承诺任意企业规模或高可用。

团队客户端通过 HTTPS 访问 AIKS；反向代理仅转发 AIKS 允许的业务入口，明确信任的代理/Host/origin，禁止任意 forwarded header 改写安全决策。思源只绑定内部地址/容器网络，不映射到员工可访问端口；Token 只留服务侧。公司内网/VPN 可作为可达网络，是否暴露公网由部署者决定，不能为回调方便直接开放思源。

用户浏览器必须能访问所配置回调地址，AIKS 服务必须能出站访问钉钉 API。钉钉登录/组织验证不是完全断网能力；断网团队登录不回退假认证。完全离线个人模式独立可用。

交付包含可验证的服务启动配置、健康检查、升级/回滚说明与业务库+思源工作区一致性备份/恢复流程。不得仅写一个 Docker Compose 就宣称团队部署验收通过。

## 10. 分段交付顺序（不是逐文件实施计划）

A. 首先建立内部稳定身份、资源所有者与只读 grant 的纯逻辑/存储边界，补未授权拒绝与个人兼容测试；此时不开放远程。
B. 接钉钉登录事务、组织只读适配、会话撤销；合成接口验证后再用专门测试企业联调，真实 Secret 由部署者本地配置。
C. 将 runtime/搜索/正文/附件/任务切到可信请求上下文，新增分享与仅所有者编辑 API。授权测试覆盖所有访问和降级路径。
D. 桌面增加可选团队连接、浏览器登录与人员/组织分享框，沿用现有知识库/采集界面；现有本地空间、上传队列目标隔离与跳过引导保持。
E. 授权及端到端测试通过后，才启用显式团队部署，验证网络隔离、备份恢复、基本并发与日志。

不把“OAuth 成功”当作团队版完成，不把只读分享当作实时协作，也不把单元测试当作真实企业授权联调。

## 11. 必须通过的验收场景

- 个人模式无公司地址/钉钉凭据仍可启动，旧知识和数据目录不变，首次设置可跳过且没有隐式采集。
- 外部企业用户、已停用成员、错误 state、过期/重放授权码、伪造身份和开放重定向全部被拒绝；Secret/登录凭据不出现在 Webview、队列、URL 和日志。
- 新上传会话和提炼知识默认为本人私有；A 无法凭 B 的文档、会话、附件、任务 ID 读取或修改。
- 分享给人员与部门可并存；下级部门选项默认关闭；上级没有隐式读取权；跨公司目标拒绝。
- 每一条授权通路撤销符合并集规则；离职/停用、部门调动及目录失效在明确时限内生效；分页中断不会清空目录。
- 共享读者可以阅读/检索，但不能编辑、分享、删除；发送 edit/write 授权请求被拒绝。
- 分享知识不泄露私有源会话及未授权附件；无法通过搜索摘要、统计、向量降级、缓存或慢正文请求获得已撤销资料。
- 创建者两窗口旧版本保存被拒绝；思源超时、重试及重启不产生重复文档，不覆盖人工作品。
- 切换团队/用户不会改写原队列目标；退出团队不停止服务进程、不删除本地资料。
- Linux/Windows、Core/Service/CLI/Desktop、前端全工作区回归通过；真实钉钉测试企业联调和真实思源验证单独记录。
