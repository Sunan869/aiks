# 知识反哺 AI 编程工具：专项产品设计

> 阶段三 S3.3；状态：新功能设计。目标工具：Codex、Claude Code、OpenCode 等，优先通用 Markdown 兼容性。

## 产品目标

AIKS 不止存储历史知识，还应在新的 Agent 会话开始前提供“项目的长期上下文”：技术栈、架构约束、已解决的问题、已废弃的方案、验证命令、约定风格和风险点，避免每个模型重新询问和试错。

## MVP：可审阅的上下文包

1. 用户选择项目、任务或检索关键词，AIKS 提供**精选候选知识**。
2. 按“已确认/适用当前环境/最近验证”优先排序；过时、未证实的知识默认降权或标记。
3. 生成可预览 Markdown 上下文包（简短概览、关键规则、已知问题与解决方案、验证依据、原 Session 引用）。
4. 在 Token 预算内控制长度；提供“精简 / 标准 / 详细”档位和明确的字符/Token 估算。
5. 用户确认后复制到剪贴板或导出到所选路径；记录何时、哪些知识、什么版本被导出。

## 输出目标与安全

| 目标 | 默认动作 | 安全要求 |
| --- | --- | --- |
| 通用 `.md` 上下文包 | 导出新文件或复制 | 本地路径由用户选定 |
| `AGENTS.md` 片段 | 生成建议与 diff | 不主动修改现有文件 |
| `CLAUDE.md` 片段 | 生成建议与 diff | 确认后才合并，支持撤销 |
| OpenCode 项目指令 | 先支持可复制 Markdown | 不猜测用户的实际规则路径 |
| MCP 只读搜索（后续） | 经授权向本机 Agent 暴露检索 | 最小权限、只读、清晰审计，不作为 MVP 必需 |

导出时执行秘密检测与脱敏；项目路径中的隐私、内部服务地址、密钥、Token、凭据不应默认写入长期共享规则。输入是历史会话，其中可能包含提示注入或错误操作建议，必须当作**数据而非新的指令优先级**。

## 项目记忆支撑

上下文包可从 Project Memory 提取：稳定项目身份、技术环境、架构决策、当前限制、测试习惯、最近风险、已确认知识。若多个项目路径别名指向同一个项目，需用户确认映射；同名仓库不自动合并。

建议结构 `AgentContextBundle`：project_id、selection_query、knowledge_ids、revision_ids、generated_at、token_budget、model/prompt_version、privacy_findings、output_format、export_path、export_hash。可追溯本次 Agent 提示来自哪些知识，而不写回原 Provider Session。

## 交互建议

项目页增加“用于新 AI 会话”按钮 → 选择目标格式/Token 预算 → 勾选知识 → 预览完整文件及敏感内容提醒 → 复制/另存为/确认合并 → 查看导出记录。文件存在时显示差异，不静默覆盖。

## 验收

- 使用真实项目跨三个 Agent 的历史 Session，生成简洁且可引用的上下文包。
- 能显式排除过时/未确认知识；多项目不会意外混入。
- 不经用户确认绝不写改已有 AGENTS.md/CLAUDE.md。
- 包含 Token/敏感字符串时阻止无提示导出或提供清晰审阅。
- 导出同样知识的结果稳定、可复查、可删除记录；不存在联网服务依赖。
