# 自动工作日报、周报与项目回顾：专项产品设计

> 阶段三 S3.2；状态：新功能设计。依赖稳定的 Session/Knowledge/Project Memory 与证据关系。

## 场景与目标

从本地工作会话生成“我这段时间到底做了什么”，支持日、周、自定义日期与项目维度。输出可以供自己复盘、项目进展整理与客户沟通，但**不能把 AI 讨论计划直接写成已完成事项**。

## 报告类型

1. **日报**：今天处理的项目、实际完成事项、问题、阻碍、待确认项与次日计划建议。
2. **周报**：项目分组、工作量趋势（仅以可观测事件统计）、关键交付、里程碑、风险、下一周优先级。
3. **项目回顾**：给定项目/迭代日期范围，梳理目标、决策变化、实施与验证、最终成果、遗留事项和可复用知识。
4. **问题专项复盘**：围绕某个缺陷或技术方向输出事件线和最终方案（依赖跨 Session 关联）。

## 生成流程

选择时间范围/项目 → 从 Session、KnowledgeItem 与项目关系筛选事件 → 聚类与去重 → 区分“完成/尝试/讨论/待验证” → 生成带来源引用的结构化报告 → 用户预览与编辑 → 保存本地草稿/导出 Markdown。

建议事件结构：event_id、project_id、session_refs、knowledge_refs、occurred_at、kind、status、evidence_snippet、evidence_confidence。报告结构：type、范围、归属、entries、citations、generated_at、model_prompt_version、draft_revisions。

## 页面和编辑

- 报告页面有“今天 / 本周 / 本月 / 自定义”及项目、数据源筛选。
- 展示报告章节与可展开的引用；点击后打开知识或源 Session。
- 允许勾选保留/删除条目、编辑描述、调整顺序、合并相近事项，保存草稿。
- 支持一键复制 Markdown、保存为本地文件、写入用户**明确指定**的 SiYuan 位置（如果实现），不自动发邮件、钉钉或外部网络。
- 相同条件重复生成时可比较修订版本，区分“重新生成”和“覆盖现有编辑稿”。

## 真实性边界

模型不得在没有测试日志/人工确认时宣称“部署成功”“已上线”。看不到源项目的 Git 状态时，不推断代码已合并。对机器猜测的完成事项给出“需核实”标记；报告默认不过度引用敏感原文，外发前做脱敏预览。

## 验收

- 以三个跨工具 Session（分析→修改→验证）生成一条不重复的工作事项。
- 多项目同名任务分开统计；同一 Session 不因多 Provider 扫描而重复计数。
- “计划做 X”不得自动升级为“已完成 X”。
- 所有重要事实有本地可点击来源；无来源时标示为总结/推断。
- 编辑过的报告重跑不覆盖，恢复/导出后内容完整。
