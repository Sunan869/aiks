# 知识质量闭环：专项产品设计

> 阶段二 S2.2；状态：规划。当前已有知识提炼、去重和编辑能力，不代表完整的质量闭环已实现。

## 目标

从“生成知识”进化为“知识值得保存、能修正、越使用越可靠”。将**机器估计质量**与**人工确认准确性**分离，防止高模型分数被误解为事实验证。

## 质量维度

| 维度 | 判断问题 | 评估证据 |
| --- | --- | --- |
| 准确性 | 结论是否符合原会话与验证结果 | 引用、执行结果、人工复核 |
| 完整性 | 条件、操作、结果是否齐全 | 上下文和必要步骤 |
| 可复用性 | 能否应用于类似工程场景 | 前提、约束、适用版本 |
| 上下文充分性 | 是否清楚描述环境/问题 | 项目、产品版本、错误消息 |
| 可追溯性 | 能否定位来源 Session/消息 | 稳定来源引用与摘录 |
| 新鲜度/时效 | 是否可能已过期 | 最近验证日期、新版替代关系 |

自动评价可以输出分项分数、理由、缺失字段和信心度，UI 显示为“AI 建议”而非“真实准确率”。

## 核心交互

1. 提炼后在 KnowledgeItem 展示质量标识、关键证据和“待验证”状态。
2. 用户可标记 **有用 / 错误 / 重复 / 过时 / 需补充**；支持添加纠正说明、适用版本、修订后的正确文本。
3. 用户确认的结论优先显示；自动重提炼不能覆盖这些人工修改。
4. 系统可定期提出复审建议：存在 newer `supersedes`、证据缺失、与其他知识疑似矛盾、很久未验证。
5. 检索与问答可以降低未验证、被否决、过时知识的权重；不能把“点赞多”当事实准确证明。

## 存储与数据流

建议 `KnowledgeQualityAssessment`：item_id、schema_version、model/prompt_version、dimension_scores、rationale、evidence_refs、timestamp；`KnowledgeFeedback`：item_id、feedback_type、comment、reviewer_local_identity、timestamp、revision_ref；`KnowledgeRevision`：修改前后、原因、来源、可恢复快照。

保存原始提炼输出、模型评估、用户编辑稿和发布到 SiYuan 的状态差异。任何知识 merge/split、SiYuan 编辑冲突都要继承或显式处理人工反馈，不能丢失。

## UI 设计

- 知识详情顶部：质量提示、最近验证时间、人工审阅状态。
- “问题反馈”操作：错误、重复、已过时、缺少条件、内容有用。
- 修订预览：对比 AI 旧稿与用户新稿，可撤销。
- 质量待办：按项目、低置信度、需复审、疑似矛盾筛选；避免制造大量无意义提醒。

## 指标和测试

建立固定匿名化样本，让人工标注：事实是否遗漏、文档是否可复用、质量评分与人工判断的相关程度、无引用率、错误/过时识别 Precision。验收包括：人工纠错重跑不丢、已拒绝项不会静默复活、同一条反馈不会重复入库、恢复后历史完整。

## 与其他模块的关系

为跨 Session 演进提供“已确认/过时”信号；为项目记忆、工作报告和 Agent 导出提供质量门槛；为搜索提供附加排序依据。阶段一稳定性完工后实施。
