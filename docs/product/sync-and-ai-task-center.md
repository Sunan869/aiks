# 同步与 AI 任务监控中心：专项产品设计

> 阶段一 S1.2；状态：待实现的 UI/诊断增强。现有 SQLite durable Pipeline、错误重试、阶段状态应继续复用。

## 用户痛点

当前用户看到“Session 同步成功”，容易以为知识已提炼并在 SiYuan 展示；实际同步、提炼、Embedding、去重和发布是独立阶段。模型超时、分卷内容冲突或来源文件不可读时用户往往只能搜索日志。监控中心必须能回答：**做到了哪一步、为什么失败、现在能做什么**。

## 页面结构

- **总览**：扫描来源数量、待同步 Session、正在处理任务、同步成功、知识完成、失败、冲突；所有数字须注明统计范围。
- **任务列表**：来源、项目、Session、当前阶段、状态、进度/时间、耗时、重试次数；可筛选、搜索。
- **任务详情**：阶段时间线（扫描→解析→同步→清洗→提炼→Embedding→去重→发布），模型调用与分块统计、可理解的错误摘要及不暴露密钥的技术诊断。
- **操作区域**：安全重试、查看 Session、查看分卷、查看知识、导出脱敏诊断；风险操作显式确认。

## 状态原则

用现有 `sync_target`、`pipeline_job`、`pipeline_run`、stage status 聚合展示，**不要新增与真实状态不一致的第二套任务队列**。区分：
- `Source imported`：源会话被读取/保存。
- `Raw synced`：原始 Session 成功写入 SiYuan。
- `AI extracted`：知识结构化生成完成。
- `Indexed`：检索索引可用。
- `Published`：知识已发布到目标 SiYuan。
- `READY`：符合当前实际 pipeline 完成约定。

如果模型或 Embedding 未启用，显示 `SKIPPED` 的具体原因，而非假装已完成。

## 故障分类及恢复

| 类型 | 示例 | 推荐交互 |
| --- | --- | --- |
| 临时性 | 网络超时、429、模型短暂不可用 | 指数退避，可手动重试 |
| 内容可修复 | JSON 输出不合法、单次解析失败 | 提示来源与安全重试 |
| 不可自动恢复 | 远端文档被用户编辑、分卷冲突 | 查看差异、人工确认 |
| 配置问题 | 模型/Embedding 未配置、路径不可访问 | 进入相关设置 |
| 来源格式问题 | Provider 不可读快照 | 报告文件位置（可脱敏）、跳过单项不清理其他历史数据 |
| 数据安全异常 | 数据库损坏/迁移失败 | 停止写入、备份与诊断 |

重试必须具备幂等键和队列去重；后台不能无限重试不可恢复错误。任务取消应仅取消未提交动作或安全阶段，不撤销已写入的用户编辑。

## 指标

采集：发现数、成功率、吞吐与扫描时延、空闲磁盘 I/O。
AI：Prompt 版本、模型端点别名（不含凭据）、总请求数、请求延迟、token、缓存命中率、失败和重试。
Sink：分卷数、发布结果、远端冲突、最后已验证 baseline。
隐私：默认日志/诊断不输出原会话正文、密码、Token 和完整敏感路径。

## 验收标准

- 模拟模型超时：UI 精确显示“原始 Session 已同步，知识提炼失败”，可安全重试成功。
- 模拟用户编辑分卷：不自动覆盖，显示冲突处理入口。
- 重启后任务状态、次数、错误历史保留；相同 Session 不会因为重复点击产生双份工作。
- 性能不会因前端高频轮询造成 SQLite/WAL 读写放大。
- Windows/macOS/Linux 显示一致；刷新和关闭窗口不会影响持久任务执行。
