# AIKS 单机离线版：完整产品能力蓝图

> 产品愿景：从多 AI 编程工具 Session 同步器，升级成**跨工具、跨 Session、跨项目的个人工程长期记忆系统**。  
> 状态：持续演进设计；已上线功能与建议功能分开记录。

## 1. 产品定位

用户使用 Codex、Claude Code、OpenCode、GitHub Copilot 等工具处理长期项目时，知识散落在数百个 Session：同一问题被重复分析、同一错误被反复修复、技术决策缺乏后续验证。AIKS 持续收集本机允许读取的对话，抽取可复用知识，组织演进关系，通过搜索、问答、报告、项目记忆和 Agent 上下文再次使用。

核心价值链：**采集 → 同步与清洗 → 提炼 → 质量评估 → 去重/关联/演进 → 项目长期记忆 → 检索/问答/报告 → 反哺 Agent**。

## 3. 典型产品场景

### A. 一个工程问题跨三种 Agent

Codex 定位 PostgreSQL 迁移异常；Claude Code 修改迁移代码；OpenCode 完成回归。AIKS 归为一个问题链：现象→原因→候选方案→采用方案→验证→适用版本。用户能查到“最终方案”，同时保留废弃方案和证据。

### B. 进入旧项目接续工作

打开某项目的 Project Memory，展示架构、依赖版本、约束、已解决与未解决问题、最近改动；不把过期配置误当现状。可生成面向新 Agent Session 的上下文包。

### C. 自动回顾本周做了什么

按项目/日期从 Session 推断工作事项，标记“已完成/讨论中/待验证”并提供点击证据。用户审阅后一键导出 Markdown 周报，不自动发送外部。

### D. 提炼任务失败后自助恢复

任务中心说明“原会话已同步，知识提炼超时”，显示阶段、原因、上次成功和模型配置，允许按阶段安全重试；用户修改过的 SiYuan 文档只能走冲突处理。

### E. 发现知识过时

系统识别旧 Redis 部署步骤与新方案存在冲突，标注“可能过时”，保留两个版本并邀请用户确认替代关系；后续检索默认优先已验证的当前方案。

## 4. 信息架构建议

桌面左侧：**工作概览 / Session / 知识 / 项目记忆 / 搜索与问 AIKS / 工作报告 / 任务中心 / 数据源与设置**。

SiYuan 仍承载知识浏览、可编辑文档与图谱呈现；AIKS 本地存储稳定身份、任务状态、关系证据与检索元数据。避免产生两套无关的知识真相。

全局交互：查看来源、回到 Session、打开关联项目、修订/纠错、生成上下文包、操作预览/取消和历史恢复。

## 5. 共用领域模型建议（概念层，不直接代表数据库表）

- `SessionRef`：source、external_id、project_identity、时间、消息范围、同步状态。
- `KnowledgeItem`：稳定 ID、标题/正文/类别、来源、版本、质量/人工审阅状态。
- `KnowledgeEvidence`：对应的 Session、消息起止/Chunk、引用片段 hash、提炼 Prompt 与模型版本。
- `KnowledgeRelation`：from/to、关系类型、置信度、证据、自动/人工来源、确认状态。
- `KnowledgeRevision`：正文修改、纠错原因、人工确认与撤销信息。
- `ProjectIdentity` / `ProjectMemoryEntry`：路径/映射、归属、事实类别、版本/时效/证据。
- `ActivityReport`：日期范围、项目、条目、证据、生成版本与人工编辑稿。
- `AgentContextBundle`：目标项目、知识快照、Token 预算、来源、脱敏报告、导出记录。
- `PipelineObservation`：每阶段状态、耗时、尝试次数、错误类别和恢复动作。

优先复用已有 `source_session`、`pipeline_job`、`KnowledgeItem`、`semantic_knowledge_relation` 与 SiYuan 映射；增加字段或表前必须核对现有 schema 和迁移规则。

## 6. AI 行为与隐私规则

- 采集到的是历史会话，**不是经过事实核验的真相**。AI 结论应标记证据等级与时间。
- 内容相关性不能替代身份一致性；禁止仅因标题相似自动合并跨项目记录。
- 默认仅本地持久化；模型调用使用用户指定的服务端点并清晰提示数据流向。
- 导出日报和上下文前检查 Token、URL 凭据、私密路径与敏感内容；保留人工最终控制。
- 任何删除、覆盖、批量归档、回写 Agent 规则等有副作用操作，都必须先预览并确认。
- 文档/向量删除与撤销需考虑 SQLite、FTS、Embedding、SiYuan 引用一致性。

## 7. 开发优先级与阶段门槛

**阶段一（P0）**：分卷同步安全 → 同步/AI 任务中心 → 备份恢复 → Provider/CI/性能基线。退出时应能“稳定使用、不丢数据、出错可诊断”。

**阶段二（P1）**：提炼性能和质量 benchmark → 人工知识质量闭环 → 关系演进/知识版本 → 可溯源搜索与问 AIKS。退出时应能“知识可信、能链接历次决策”。

**阶段三（P1/P2）**：项目长期记忆 → 日报/周报/项目回顾 → Agent 知识包 → 安全自然语言整理。退出时应能“知识能反复产生工程价值”。

可选后续：Windsurf、更多真实 Provider、知识图谱可视化、本地 ANN、只读 MCP 服务。不要抢在可靠性与证据关系之前。

## 8. 跨模块一致的验收指标

- 稳定性：重复同步重复文档数、冲突误覆盖数、恢复成功率、无损备份/恢复率。
- 提炼：结构化合法率、事实遗漏率、P50/P95、模型 Token 与缓存命中率。
- 检索：Recall@K / MRR 或人工相关性评审、引用准确率、无证据回答率。
- 关联：正确关系 Precision/Recall、误跨项目率、人工修订后复现率。
- 产品：任务失败可定位时间、报告编辑率、知识包复用成功率。

建立匿名化固定样例，先采集基线再设置可量化阈值。不要虚构当前测量结果。
