CURSOR · COMPOSER HISTORY

Find Cursor Composer conversations across local workspaces

Cursor history can live in editor workspace databases, Composer records, or separate Agent transcripts. AIKS treats Cursor and Cursor Agent as different provider types so you can inspect supported formats without assuming that every Cursor chat layout works.

Download AIKS ↗ See supported sources

Where does Cursor store conversation history?

For supported Cursor Composer layouts, AIKS reads relevant records in User/globalStorage/state.vscdb and User/workspaceStorage/<workspace>/state.vscdb. Cursor Agent is a separate provider for JSONL transcripts under ~/.cursor/projects/<project>/agent-transcripts/. Support is format-specific and does not imply that every Cursor version or chat schema is covered.

How to search and reuse the records

  1. Choose the correct provider

    Open Data Sources. Check Cursor for Composer databases and Cursor Agent for agent transcript JSONL files. Their provider identities and formats are distinct.

  2. Verify the editor User directory

    Windows, macOS, Linux, portable profiles, and remote setups can use different paths. Set a known absolute path when auto-discovery does not match your installation.

  3. Import and search read-only

    Scan the supported sources and filter Work Records by provider or project. For damaged databases or incomplete writes, inspect diagnostics rather than changing the original SQLite file.

  4. Extract verified findings

    Optionally enable extraction for useful decisions, implementation details, and debugging steps, while retaining access to the original source session.

Why not promise every Cursor conversation?

Cursor changes internal storage layouts. AIKS supports bounded Composer JSON, referenced bubble records, and some older workspace Composer variants. Other schemas are not covered by a blanket compatibility guarantee. Test against the version you actually use.

Compatibility and privacy boundaries

  • Cursor Composer SQLite and Cursor Agent JSONL are separate providers with different storage roots.
  • Source databases are read-only; unrelated credentials and editor settings are not collected.
  • Disabling a source does not automatically remove already imported work records. Unknown formats need new evidence and parser tests.

Check actual parser coverage rather than assuming every tool version is supported. Provider compatibility matrix.

Frequently asked questions

Are Cursor and Cursor Agent one provider?

No. One handles supported Composer database layouts, while the other handles separate Agent transcript JSONL.

Why is an older Cursor chat missing?

It may use another workspace path, an unsupported layout, or an unverified version. Check provider diagnostics and the compatibility matrix.

Will AIKS modify Cursor's database?

No. Supported SQLite/WAL source data is read-only and never intentionally rewritten by AIKS.
