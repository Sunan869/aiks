CLAUDE CODE · SESSION HISTORY

Find and reuse Claude Code conversation history locally

A debugging fix or architecture decision often ends up buried inside an old Claude Code session. You can review the original records first, search across your work, and optionally turn verified findings into reusable notes. AIKS reads supported local provider data without modifying it.

Download AIKS ↗ See supported sources

Where does Claude Code keep its local session history?

Claude Code commonly stores project-related session files under .claude/projects/ in the user home directory, often as JSONL. The actual location may vary by platform, version, or custom configuration. Confirm the path from your installed tool and the AIKS Data Sources page.

~/.claude/projects/

How to search and reuse the records

  1. Locate the provider

    Open AIKS Data Sources and find Claude Code. Check the detected path and provider status; set an absolute directory if your installation uses a custom location.

  2. Scan read-only session records

    Enable the provider and scan. Open Work Records and filter by project, source, or title to verify that historical sessions were imported correctly.

  3. Search existing content

    Look up an error message, framework, command, or configuration change. Basic full-text search works without an AI model.

  4. Extract knowledge only if useful

    Configure an AI endpoint before enabling extraction of reusable findings. Semantic search requires a separate embedding service and remains optional.

Example: recovering a previous fix

If you already solved a .NET build failure, search the error text and examine the original messages, attempted commands, final fix, and assumptions. AI-generated summaries are pointers back to evidence, not replacements for it.

Compatibility and privacy boundaries

  • AIKS does not log in to Claude or download all private cloud account history. Local Claude Code files are a separate source.
  • Custom profiles, changed storage layouts, and moved project directories may require provider path adjustments.
  • Provider files remain read-only. AIKS knowledge records and optional SiYuan documents are stored separately.

Check actual parser coverage rather than assuming every tool version is supported. Provider compatibility matrix.

Frequently asked questions

Can I search without configuring a model?

Yes. Browsing imported sessions and keyword search do not require model inference. Extraction and AI Q&A need a configured AI endpoint.

Does AIKS edit my Claude Code session files?

No. It reads supported local source files without writing to them.

Does this import all Claude web account chats?

No. Local Claude Code history is not the same as private conversations in a Claude web account.
